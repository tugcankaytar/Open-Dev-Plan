# Changelog

All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [SemVer](https://semver.org/).

## [Unreleased]

### Added
- Project skeleton: `uv`-managed Python package, FastAPI app, SQLite schema + migration runner (WAL, FTS5, sqlite-vec).
- Local LLM provider abstraction (`LLMProvider` Protocol) with an Ollama backend and an in-memory fake for tests.
- Structured-output generation with schema validation and a single repair pass.
- Durable, GPU-coordinated background job queue (`jobs` table + worker + single-slot GPU semaphore).
- `/api/health` endpoint reporting DB and Ollama/model availability.
- CI (lint, format check, type check, tests), pre-commit hooks, contribution/security docs.
- Data layer: repositories for projects, meetings (+ transcript segments), tasks (+ dependencies), and proposals.
- Deterministic scheduling engine (interval merge/conflict-detection + free-slot search) with an LLM used only to parse natural-language intent, never to compute dates or resolve conflicts itself.
- `.ics` calendar export/import with RRULE support, round-trip tested.
- Meeting extraction pipeline: versioned prompts, action-item/decision/summary extraction, map-reduce chunking for long transcripts, embedding-based dedup, and a proposal-only write path (nothing is ever written to a domain table without human approval).
- Proposal resolution (`approve`/`edit`/`reject`): turns an approved/edited task proposal into a real `Task` with a deterministically-resolved due date; every resolution is logged to `training_examples` for future fine-tuning.
- Full HTTP API (projects/tasks/meetings/calendar/proposals/schedule-suggest) plus an SSE job-progress stream, wired to a real background worker.
- Eval harness (`evals/`) comparing candidate extraction models on a small golden set; used to pick `gpt-oss:20b` as the default for both extraction and Turkish prose generation (see `evals/README.md`).
- Fine-tuning dataset export script (`training/export_dataset.py`) and a documented LoRA runbook (`training/README.md`).
- Live end-to-end test against real local models (`pytest -m gpu`), verifying the full meeting → extraction → proposal → approval → task flow.
- `POST /api/meetings/{id}/transcript/import-text`: paste/type a transcript to exercise the extraction pipeline before real audio transcription exists.
- React + TypeScript web UI (Vite, TanStack Query): dashboard, projects, meetings (with transcript paste, live extraction trigger, SSE job progress, and inline proposal approve/edit/reject), a task Kanban board, a natural-language scheduling assistant, and calendar import/export. Built and served as static files by the same FastAPI process (`uv run odp serve` alone is now a complete app); `npm run dev` for hot-reload development against a separately-running backend.
- Verified live end-to-end through the running app (not just tests): create a meeting → paste a Turkish transcript → real `gpt-oss:20b` extraction → review proposals → approve → confirm the resulting Task, including correct deterministic due-date resolution ("friday" → the correct calendar date).
- Dashboard stats (`GET /api/stats/dashboard`): active project/open-task/meeting/pending-proposal counts, a task-status breakdown, and a 7-day created-vs-completed activity series — plain SQL aggregation, no LLM involved.
- A chat assistant that answers from the app's own data: `services/chat/` assembles a context snapshot (active projects, open tasks, recent meeting summaries, recent decisions) and streams a reply via a new `LLMProvider.stream_chat` method over `POST /api/chat` (SSE via a POST body, not GET+EventSource).
- Runtime model switching: an `app_settings` table + `GET`/`PUT /api/settings/model` let the sidebar's model picker change the active model (used by extraction, chat, and schedule-intent parsing) without a restart.
- Redesigned web UI on a "technical studio" design system (dark sidebar, violet/cyan accents, Space Grotesk + IBM Plex typography) — first drafted as a published design canvas, then implemented: real charts fed by live stats, a persistent collapsible chat panel, a functional model picker, and a refreshed icon set (no emoji) across every page.
- Customer entity (`customers` table + repository + `/api/customers` CRUD), linkable to projects; the Projects page and the task-creation form both offer a customer → project cascading select.
- Richer task records: priority (low/medium/high/urgent), a start date alongside the due date, free-text tags, and a per-task checklist (subtasks) — `task_checklist_items` table, computed `checklist_total`/`checklist_done` on every `Task` via a JOIN (no N+1 queries for Kanban cards). Creating or editing a task now opens a full popup form (`TaskFormModal`) instead of a bare title input.
- Real calendar month view (`MonthCalendar`) replacing the placeholder list; `.ics` import/export moved into popups so they no longer take up permanent screen space.
- Draggable Kanban board (`@dnd-kit`) with a Kanban ↔ list view toggle for tasks.
- Chat assistant tool-calling expanded to full parity with the UI: create/update/delete for customers, projects, tasks, and meetings; checklist add/toggle/delete (by title, with an ambiguous-match error when more than one item matches); pending-proposal approve/reject — all 15 tools, covering everything a user can do by hand. Every destructive (delete) tool requires a `confirmed: true` argument the model may only send after the user explicitly confirms in chat; checklist-item deletion is exempt (small, easily reversible). Verified live end-to-end against real `gpt-oss:20b`: the assistant asks for confirmation before deleting, refuses the tool call without `confirmed: true`, and completes the deletion once the user says yes.
- Live data flow across the whole app: a lightweight SSE broadcaster (`services/events.py`, `GET /api/events`) publishes a scope name after every mutating write (including background extraction jobs); the frontend (`useLiveEvents` hook, wired into `Layout`) subscribes once and invalidates the React Query cache on every event, so records created by the user *or* by the chat assistant appear instantly with no page refresh, anywhere in the app.
- Meetings can now be linked directly to a customer (independent of any project) — `meetings.customer_id`, exposed in the UI (Meetings list + detail) and to the chat assistant (`create_meeting`/`update_meeting` accept `customer_id`).
- A project can now belong to more than one customer — `customer_id` moved to a `project_customers` join table (migration backfills existing single links before dropping the old column); the Projects page uses a checkbox multi-select, and the chat assistant's `create_project`/`update_project` tools take a `customer_ids` array.
- Task dependencies (`add_task_dependency`/`remove_task_dependency`) and a natural-language meeting-slot suggestion tool (`suggest_meeting_slot`, wrapping the existing deterministic scheduler) are now exposed to the chat assistant — found and closed while stress-testing the assistant against real usage; both were already fully built at the data/service layer but had no way to be reached from chat.
- Found by the same stress-testing pass and fixed: `from_utc_iso()` crashed on any timestamp carrying milliseconds (the browser's `Date.toISOString()` always includes them), which silently broke `.ics` export and the scheduling assistant for every meeting created through the web UI — parsing is now tolerant of fractional seconds, and `POST/PATCH /api/meetings` and `/api/tasks` now normalize client-supplied timestamps to the canonical storage format before writing. Meetings can no longer be created or updated with an end time at or before the start time (422).
- Two chat-tool robustness fixes found live against `gpt-oss:20b`: a harmony-format channel marker (`<|channel|>commentary`) the model occasionally leaks into a tool call's name is now stripped before dispatch (was silently failing as "unknown tool" and burning a tool-calling round); a tool call that sends a generic `id` instead of the schema's entity-specific key (`project_id`, `task_id`, `meeting_id`, ...) now falls back to it instead of erroring.
